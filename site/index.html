01

每台服务器一张卡片One card per server

鼠标移到刘海上就展开。集群和工作站分开显示，每张卡片上有自己的运行数、排队数、CPU / 内存 / GPU。没有任务的机器自动合并成一行，不占地方。 Hover the notch to expand. Clusters and workstations each get a card with their own running / pending counts, CPU, memory and GPUs. Idle servers fold into a single line.

  • 读取 ~/.ssh/config，跳板机、密钥都照常生效Reads ~/.ssh/config — ProxyJump and keys just work
  • 动态口令集群：输入一次，连接一直保持OTP clusters: log in once, stay connected
  • 每台机器可以单独暂停、静音、设轮询间隔Pause, mute or set the interval per server
02

Slurm：数组、排队原因、分区空闲Slurm: arrays, pending reasons, free nodes

几十个元素的数组作业合并成一行，绿 / 红 / 蓝分段显示完成、失败、运行中。排队原因翻译成人话；需要你处理的（比如依赖永远无法满足）会标红。还能按需查看各分区还有多少空闲 CPU 和 GPU。 Job arrays collapse into one row with done / failed / running segments. Pending reasons are explained in plain words, and the ones that need you are flagged. Check free CPUs and GPUs per partition on demand.

03

完成和失败，刘海会告诉你The notch tells you when it's done

任务结束时刘海弹出提示，成功和失败是两种不同的提示音。没有开启作业记录的集群，也会按计算软件的输出判断是正常结束还是提前退出，不靠猜。 When a job ends, the notch pops up — with different sounds for success and failure. Even on clusters without job accounting, ServerIsland checks the software's own output to tell a clean finish from an early exit.

04

点开就是详情和日志末尾Details and log tail, one click away

作业信息、工作目录、实时刷新的日志末尾，一键复制路径或 tail -f 命令。取消任务默认关闭；打开后也要长按、二次确认，执行前还会在服务器上再核对一遍。 Job info, working directory and a live log tail; copy the path or a tail -f command in one click. Cancelling is off by default — and even when on, it takes a long press, a confirmation and a server-side re-check.

认识你的计算软件Knows your simulation software

按工作目录里的文件判断，只读文件末尾。格式和预期不一致时宁可不显示，也不给你一个错的进度。 Detected from files in the working directory, reading only their tails. If anything doesn't match, it shows nothing rather than a wrong number.

只在你的 Mac 上运行Runs only on your Mac

没有账号、没有云端、不收集任何数据。所有连接都是你的 Mac 直接 ssh 到你的服务器。No account, no cloud, no telemetry. Your Mac talks to your servers over ssh, and that's it.

用系统自带的 sshUses the system ssh

不保存密码。需要密码或动态口令的机器，用系统原生对话框输入，连接复用后不再打扰。No stored passwords. Password / OTP prompts use a native dialog, then the connection is reused.

轻量到感觉不到Featherweight

每台机器每轮一个 SSH 通道，只读小文件和文件末尾；可以按机器调间隔，或只手动刷新。One SSH channel per server per poll, reading only small files and tails. Tune the interval per server, or refresh manually.

第一次打开提示"无法验证开发者"？"Cannot verify the developer" on first launch?

ServerIsland 没有经过 Apple 公证，第一次打开时 macOS 会拦一下，只需要允许一次： ServerIsland isn't notarized by Apple, so macOS blocks the first launch. You only need to allow it once:

  • macOS 15 及以后：先双击打开一次（会被拦住），然后到 系统设置 → 隐私与安全性，往下找到 ServerIsland，点"仍要打开"。 macOS 15 and later: double-click the app once (it will be blocked), then open System Settings → Privacy & Security, scroll down and click "Open Anyway".
  • macOS 14：按住 Control 点 App 图标，选"打开"，再点"打开"。 macOS 14: Control-click the app icon, choose Open, then Open again.

或者在终端里执行一行命令：Or run this once in Terminal:

FAQ

要钱吗？Is it free?

完全免费，源码在 GitHub 上，GPL-3.0 许可证。Yes. It's free software under the GPL-3.0 license.

服务器上需要装什么吗？Do I need to install anything on the server?

不需要。ServerIsland 通过 ssh 发送一小段 bash 脚本，读取 squeue、nvidia-smi、/proc 和计算软件的输出文件，不写任何东西。No. It sends a small bash script over ssh that reads squeue, nvidia-smi, /proc and your output files. It never writes anything.

没有刘海的 Mac 能用吗？What about Macs without a notch?

可以。没有刘海的屏幕会在顶部中间显示一个虚拟的岛，用法完全一样。Yes — screens without a notch get a virtual island at the top center that works the same way.

我的软件不在支持列表里？My software isn't supported?

在设置 → 进度识别里加一条自定义规则：指定文件和关键字（或正则），可以当场在服务器的真实目录上测试。只要你的程序会把进度写进文件，就能识别。Add a custom rule under Settings → Progress Detection: a file plus a keyword or regex, testable on a real directory right away. If your program writes its progress to a file, ServerIsland can read it.

支持 PBS / LSF 吗？Windows 呢？PBS / LSF? Windows?

目前只支持 Slurm 和直连服务器，只有 macOS 版。Currently Slurm and direct servers only, on macOS only.

会不会误取消我的作业？Could it cancel a job by accident?

取消功能默认关闭，需要在每台服务器的设置里单独打开。打开后也要长按按钮、再确认一次；执行前还会在服务器上核对作业号和运行时间，对不上就不执行。Cancelling is off by default and must be enabled per server. Even then it takes a long press and a confirmation, and the job ID and runtime are re-checked on the server before anything runs.
